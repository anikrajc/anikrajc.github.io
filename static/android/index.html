Toolchain

The things I reach for, and what I think each one is for.

Only run what changed :test --affected

A PR that touches one module shouldn't pay for the whole suite. Work out the affected modules from the Gradle graph and run just those tests. That's faster feedback and a smaller CI bill.

Make regressions loud verifyEvents

Analytics events break quietly. Check them automatically in tests so a missing or wrong event fails a build, not a dashboard three weeks later.

Measure on real hardware macrobenchmark

Emulators don't tell you about jank. Use real devices, keep them plugged in, and look after their batteries so they last.

com.anikrajc.droidkit

DroidKit

An Android toolkit for the fiddly parts of testing an app: firing deep links, flipping developer settings, checking the network. Everything stays on the device.

No analytics · no account · no ads

DroidKit's developer toggles save you digging through Settings. These tiles do the same for this page. Try one.

Deep link runner

Fire any URI at the app you choose, see which installed apps can handle it, and keep a starred history of the ones you use.

Floating bubble

An optional launcher that sits over other apps, so you can re-run a deep link without leaving the screen you're testing. Off by default.

Developer toggles

Layout bounds and animation scales in one tap. Needs WRITE_SECURE_SETTINGS, which you grant once over adb.

Network inspector

Read-only network and Wi-Fi status, for when a bug depends on the connection.
